# Remaining implementation work and explicit limits

This delivery advances the prototypes into an operationally testable software build. It does not complete every production feature in the master specification. Existing software tests must not be mistaken for a certification of sport correctness or artwork approval.

- TVG: all 35 required codes have registry entries and engineering rendering branches, samples, captures and independent comparison metrics. Their approval status is NOT APPROVED. The list backgrounds, clock naming, medal icons, certain presentation assets and exact variant geometry are unresolved. The non-priority templates contain partial field/layout behaviour. The advanced clock variants still need approved distance/record field presentation; false-start/qualification pictogram placement and medal/relay layouts require independent source-accurate completion. SFS003 is not yet connected to a complete approved session schedule. SFS206 has athlete and university rendering and native static-asset checks; this is not full per-template pixel approval.
- No missing blue bar is reconstructed from other sprites, no CSP clock is silently substituted, and no replacement medal icon is generated. A missing sprite is visibly diagnosed. Actual program output remains gated in VENUE mode; TEST previews show their engineering state.
- Timing: receive-only serial management, buffering, strict versioned parsing, durable spool, raw retention, retry, replay and rejection logic are implemented and software-tested. Actual firmware, physical wiring, message variants, corrected-time behaviour and source completeness still need vendor/device verification. The manual-reconstructed reaction format is provisional until verified against SwimTime. SwimTime Network Display, LENEX/Splash and Hy-Tek adapters are assessed but not implemented because their approved interface contracts and real samples are absent.
- Results: official approval, provenance, Jury correction, equal hundredth proposals, FISU Team exclusion and relay order validation are implemented. Full sport rule certification, automatic draws/seeding, record baselines, qualification engines, penalty/IRM mappings, federation result imports and ORIS/PDF report generation are not implemented. Qualifications, records and medals can only be recorded as documented Jury decisions; none is inferred from a raw time comparison.
- Infrastructure: a single SQLite/WAL server is implemented. PostgreSQL migration, automatic database replication, multi-server leader failover and automatic offsite backup are not included. A local read-only publication API and HTML results page are implemented, but no public website or supplier integration is deployed.
- Broadcast: Browser Source output only. No SDI/NDI/key-fill device driver, hardware mixer automation, transition Wipe integration, SMPTE timecode or physical video genlock is implemented. Preview/program/clear and non-clock hold are software-tested.
- LED: six native software canvases, independent/group routing, safe margins, full-screen URL entry and server-epoch playlists are implemented. Custom LED designs await FISU/LOC approval. Physical output mapping, LED player startup policy, colour/scan configuration, refresh, brightness and viewing-distance testing require the supplier.
- Windows: scripts, built frontend and CPython 3.12 Windows x64 wheels are supplied. The Python installer, signed EXE/MSI, Windows service registration and a witnessed Windows 11 installation are not included. The package has been run and tested on Linux, not on the user's Surface.

Resolve these limits through the source/asset registers and the production acceptance checklist. The system must remain labelled as an engineering build until the relevant owners sign its acceptance records.
