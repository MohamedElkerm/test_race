FINS 2026 — دليل ربط SwimTime
الإصدار التجريبي v0.8 / 24 أكتوبر 2026

ما الذي أضيف؟

استقبال رسائل SwimTime عبر UDP داخل لوحة FINS، وعرض الساعة وأزمنة القنوات في تبويب SwimTime TEST، وحفظ التسجيل الخام. المطابقة مع شاشة الاختبار المرسلة شملت أزمنة القنوات العشر. جميع القيم TEST، واعتماد الحارات الفعلية وأحداث النهاية واختبار النسخة الجديدة على Windows ما زال مطلوبًا.

هذه النسخة لا تنشئ نتائج رسمية من رسائل Network Display، ولا ترسل هذا التدفق تلقائيًا إلى TVG أو LED.

1. الأجهزة وعناوين الربط الحالية

الجهازالعنوان الحاليالمهمة
جهاز SwimTime10.227.186.112SwimTime + Relay
جهاز FINS10.227.186.166لوحة التحكم + UDP 26
جهاز OBS المستقليحدد عنوانه محليًاالبث وتجميع الكاميرات

العناوين من آخر تجربة ناجحة؛ راجع IPv4 على الجهازين عند تغيير الشبكة. يعمل المسار محليًا دون الإنترنت بعد التثبيت. تجربة Wi-Fi الحالية اختبار ربط؛ اختبار LAN السلكي الميداني مطلوب للتشغيل الرسمي.

2. تحديث برنامج v0.7 الموجود دون إعادة التثبيت

  1. فك ضغط حزمة v0.8 في مجلد جديد، وافتح FINS2026_LIVE_RESULTS الموجود بداخلها.
  2. أوقف خادم FINS القديم بالضغط على Ctrl+C في نافذته، وأغلق نافذة RUN_FINS_MONITOR.cmd على جهاز FINS لتحرير UDP 26.
  3. في مستكشف الملفات افتح مجلد البرنامج القديم الذي يحتوي على RUN_SINGLE_TEST_LAN.cmd. اضغط Ctrl+L ثم Ctrl+C لنسخ مساره.
  4. من مجلد v0.8 الجديد شغّل UPDATE_EXISTING_v07.cmd. ألصق مسار المجلد القديم دون علامتي اقتباس، ثم Enter.
  5. الأداة تحفظ نسخة من الكود وقواعد SQLite داخل backups\v08-update-… بالمجلد القديم، ثم تحدث الملفات المحددة. تبقى قواعد البيانات وحساب المشغّل وكلمة مروره والأصول الأصلية في أماكنها.
  6. بعد ظهور Update complete، افتح مجلد البرنامج القديم الذي تم تحديثه وشغّل منه RUN_SWIMTIME_TEST_LAN.cmd.
  7. افتح http://127.0.0.1:8765 وسجّل الدخول بحسابك الحالي. اضغط Ctrl+F5 عند الحاجة لتحديث الواجهة.

إذا كان TCP 8765 أو UDP 26 مشغولًا تتوقف الأداة دون تطبيق التحديث. أغلق الخادم أو أداة الاستقبال القديمة وأعد المحاولة. لا توقف الأداة SwimTime أو تغير إعدادات COM.

3. التثبيت في مجلد جديد عند الحاجة

  1. استخدم Python 3.12 64-bit مع Windows Python Launcher.
  2. شغّل INSTALL_SINGLE_OPERATOR.cmd. عجلات Windows مضمنة والواجهة مبنية مسبقًا؛ لا يحتاج جهاز التشغيل إلى Node.js.
  3. اقرأ بيانات الدخول الجديدة محليًا من runtime\SINGLE_TEST_CREDENTIALS.txt. لا ترسل هذا الملف مع السجلات.
  4. شغّل RUN_SWIMTIME_TEST_LAN.cmd وافتح لوحة التحكم.

إجراء Windows موجود بالحزمة؛ تشغيل v0.8 على جهاز الموقع يحتاج اختبار قبول. الاختبارات المحلية نُفذت على Linux مع Python 3.12 ومتصفح Chromium.

4. الربط المباشر مع جهاز SwimTime

  1. على جهاز FINS: افتح تبويب SwimTime TEST. أدخل مصدر SwimTime 10.227.186.112 والمنفذ 26، واضغط Start UDP TEST listener.
  2. على جهاز SwimTime: اترك Enable display via network مفعّلًا واختر Send only local ثم OK.
  3. شغّل SWIMTIME_PC\RUN_RELAY.cmd على جهاز SwimTime. يمكن استخدام مجلد Relay السابق؛ النقل نفسه لم يتغير.
  4. راقب RECEIVING TEST DATA وعدّاد Datagrams في FINS. تظهر الساعة عند وصول RunningTime غير سالب ومتقدم.
  5. نفّذ شوط TEST بالمحاكي. تظهر LaneTime غير السالبة في جدول القنوات. ترقيم القنوات مطابق للصورة التجريبية فقط؛ يلزم اختبار الحارات الفعلية قبل اعتماده.

مدة Relay الحالية خمس دقائق فقط. ينتهي الملف القديم بعد 300 ثانية، فتظهر حالة فقد البيانات. شغّل Relay مرة أخرى لمواصلة الاختبار. مستمع FINS الجديد يستمر حتى Stop أو إغلاق الخادم.

مستمع FINS المدمج وأداة RUN_FINS_MONITOR يستخدمان نفس المنفذ؛ شغّل مستمعًا واحدًا على جهاز FINS. يبقى Relay على جهاز SwimTime المنفصل.

5. إعادة عرض السجل دون جهاز التوقيت

أوقف مستمع UDP واضغط Replay recorded TEST capture. يقرأ البرنامج السجل المرفق ذي 2,754 رسالة بعد فحص بصمته ويعرض القنوات العشر. الحالة RECORDED TEST REPLAY تعني تسجيلًا سابقًا. الساعة النهائية مخفية لأن آخر RunningTime في السجل -1.

7. الحالات والتنبيهات

STALE / DATA LOSTلم تصل رسالة صالحة لأكثر من 3 ثوان. تختفي الساعة وتبقى آخر قيم الاختبار مع تنبيه واضح.
التغذية تصل والساعة مخفيةآخر قيمة سالبة أو Ready، أو لم تتقدم الساعة لأكثر من ثانيتين. القيم السالبة تبقى رموزًا خامًا.

تعود التغذية عند وصول الرسائل دون إعادة تشغيل الخادم. بعد إعادة تشغيل الخادم يبدأ المستمع متوقفًا ولا يستأنف ساعة قديمة. لا يقيس هذا الاختبار التأخير من ALGE إلى الشاشة، ولا يثبت فقد أو ترتيب جميع الحزم لغياب أرقام تسلسل موثقة.

8. السجلات والرجوع وحدود الاعتماد

التسجيلات الجديدة في runtime\swimtime\udp26-integrated-….jsonl، مع البايتات الأصلية والمصدر والتوقيت وتقسيم الملف عند نحو 32 MiB. يسجل Audit هوية من بدأ أو أوقف المستمع أو أعاد السجل.

التقرير: SwimTime_v08_Verification.md. المطابقة الرقمية: field_screen_match.json. أدلة الاختبار: testing\reports\v08.

الأصول الأصلية ومشتقات FISU لم تتغير. تبقى مراجعات TVG وLED واعتماداتها السابقة معلقة؛ هذه النسخة لا تحمل اعتمادًا إنتاجيًا. ظهور البيانات في SwimTime TEST لا ينشرها في البث أو LED. عطّل Simulator بعد الاختبار وقبل المنافسات.

للرجوع: أوقف FINS واستعد الملفات من backups\v08-update-…\code إلى مواضعها. التحديث لم يغير قاعدة البيانات؛ توجد نسخة متسقة منها في نفس مجلد النسخ الاحتياطي عند الحاجة.
