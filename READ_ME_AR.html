FINS 2026 — الإصدار 0.7

مشغّل واحد + جهاز بث مستقل + جرافيك شفاف عبر الشبكة المحلية. إصدار 23 أكتوبر 2026.

نسخة هندسية قابلة للاختبار. ربط جهاز ALGE الفعلي وOBS الفعلي وWi-Fi في الموقع يحتاج تجربة ميدانية. تصحيح هوية النتائج السابق مضمّن، لكن الأصول الناقصة ومطابقة FISU واعتماد تخطيطات LED ما زالت معلّقة.

ما أضيف

  • حساب واحد باسم operator يدير اختيار السباق والتوقيت والنتائج والجرافيك وشاشات LED والنسخ الاحتياطي. كلمة المرور فريدة وتُنشأ محليًا؛ لا توجد كلمة مرور مشتركة داخل الحزمة.
  • مخرج Program مستقل بدقة 1920 × 1080 وخلفية شفافة، مع بقاء المعاينة منفصلة عن الإرسال.
  • تبويب Connections لإنشاء رابط OBS، وتشغيل فحص اتصال لمدة 60 ثانية، وتنزيل تقرير مقاس من الكمبيوتر الذي يجري عليه الفحص.
  • فحص ملفات GEN الأصلية للإصدار SwimTime 2.4.10.1 دون تبني أي عمود كزمن رسمي أو ترتيب أو حارة.
  • معالجة توقف تدفق WebSocket: مسح الجرافيك عند فقد الاتصال وإعادة المحاولة. معالجة غياب randomUUID في اتصالات HTTP المحلية.

التثبيت على جهاز النظام

  1. أوقف النسخة السابقة بـ Ctrl+C، واحتفظ بمجلدها وقاعدة بياناتها كنسخة احتياطية. فك ZIP الجديد في مجلد جديد؛ لا تستبدل runtime أو ملفات النسخة السابقة.
  2. ثبّت Python 3.12، إصدار 64-bit، مع Python Launcher. حزمة العجلات الموجودة تستهدف Python 3.12/Windows 64-bit؛ لا تعتمد على نسخة Python تجريبية 3.16 لهذه الحزمة.
  3. افتح INSTALL_SINGLE_OPERATOR.cmd من جذر المشروع. يستخدم ملفات Python المضمّنة داخل installers/wheels-win64 ولا يحتاج Node أو npm على كمبيوتر التشغيل.
  4. افتح محليًا runtime\SINGLE_TEST_CREDENTIALS.txt لمعرفة كلمة مرور الحساب operator. احتفظ بهذا الملف على جهاز التشغيل، ولا ترسله لجهاز OBS.
  5. شغّل RUN_SINGLE_TEST_LAN.cmd. افتح http://127.0.0.1:8765 وسجّل الدخول بالحساب السابق.

تُنشأ قاعدة اختبار منفصلة باسم runtime\single_test.sqlite3 مع بيانات موسومة TEST. إعادة التشغيل تحفظ الحساب والبيانات. هذا الإصدار لا ينقل قواعد v0.6 تلقائيًا. سكربت VENUE ينشئ قاعدة مستقلة فارغة؛ تبقى قوالب الإنتاج غير المعتمدة محجوبة.

الربط بجهاز OBS

  1. وصّل كمبيوتر النظام وجهاز OBS بالشبكة المحلية نفسها. افتح موجه الأوامر على كمبيوتر النظام واكتب ipconfig، ثم حدد IPv4 لكارت Ethernet أو Wi-Fi المستخدم فعليًا.
  2. اسمح لخدمة Python عبر Windows Firewall على الشبكة الخاصة Private، بمنفذ TCP 8765 للأجهزة المحلية. سكربت التشغيل لا يغيّر الجدار الناري تلقائيًا.
  3. من جهاز OBS افتح المتصفح على العنوان التالي، مع استبدال المثال بعنوان كمبيوتر النظام الحقيقي:
http://192.168.50.20:8765/broadcast_tvg/setup.html

إذا لم تفتح صفحة الإعداد فلا تبدأ بتغيير OBS؛ راجع عنوان IP، والجدار الناري، واتصال الجهازين، وعزل أجهزة Wi-Fi.

  1. في OBS اختر Sources ثم + ثم Browser. عطّل Local file، والصق رابط Program التالي بعد تعديل IP:
http://192.168.50.20:8765/broadcast_tvg/?program=1
  1. اضبط Width = 1920 وHeight = 1080. ابدأ 30 FPS للاختبار، ثم وحّد معدل الإطارات مع فريق البث. احتفظ بالخلفية الشفافة في Custom CSS، وضع المصدر أعلى مصادر الكاميرات.
  2. اترك Shutdown source when not visible وRefresh browser when scene becomes active غير مفعّلين أثناء الاختبار.
  3. من لوحة FINS اختر قالب SFS206 وسباق TEST، واكتب سبب العملية، ثم Load preview وبعده TAKE. استخدم CLEAR GRAPHICS لإزالة الطبقة؛ تبقى الشاشة شفافة. قالب SFS206 نقطة اختبار لأصل متاح، وليس قالبًا معلنًا مطابقًا أو معتمدًا.

عندما يكون Program فارغًا فلن ترى جرافيك، وهذا سلوك متوقع. لا تستخدم رابط Dashboard أو LED أو Preview بدل رابط Program في OBS. بيانات TEST وتحذيرات القوالب تبقى ظاهرة؛ لا تُخفِها لتقديم الاختبار كبث رسمي.

هل يمكن استخدام Wi-Fi الآن؟

نعم، للتجربة الحالية بين جهاز النظام وجهاز OBS. استخدم نقطة وصول محلية واحدة واتصالًا قويًا؛ يُفضّل 5 GHz إذا كانت تغطي المسافة جيدًا. تجنّب شبكة الضيوف وعزل الأجهزة Client/AP isolation، وراقب تغيّر IP عند إعادة الاتصال. لا تحتاج الشبكة إلى إنترنت.

الرابط يرسل بيانات وأصولًا للمتصفح، وليس بث فيديو HDMI عبر Wi-Fi؛ جهاز OBS يرسم الجرافيك محليًا. لكن أي انقطاع يوقف تحديث البيانات، لذلك يبقى Ethernet السلكي هو الخيار الموصى به للتشغيل الرسمي.

افتح صفحة setup من جهاز OBS، واختر WI-FI TEST ثم Start 60-second check. بعد اكتماله اضغط Download measured report. كرر تجربة TAKE وCLEAR وفصل الاتصال وإعادته. بعد نجاح التجربة القصيرة شغّل اختبارًا أطول أثناء حركة مشابهة للمنافسات؛ لا يُعد فحص 60 ثانية اعتمادًا إنتاجيًا.

التقرير يقيس زمن الذهاب والعودة HTTP وفواصل وصول رسائل WebSocket فقط. لا يقيس زمن ALGE إلى البث ولا جودة حواف الجرافيك داخل OBS. الاتصال المعلن في التقرير اختيار المستخدم، وليس كشفًا تلقائيًا لنوع الشبكة.

بيانات الاختباريمكن تشغيل Run TEST race داخل Control لإجراء تجربة البرنامج والبث؛ رسائل اصطناعية موسومة وليست سجل ALGE فعليًا.

إذا كانت البوابة على كمبيوتر SwimTime نفسه يمكن إبقاء Send only local. إذا كانت على كمبيوتر آخر، يكون Broadcast in the network هو خيار الاختبار على نفس الشبكة الفرعية. نجاح صفحة OBS عبر Wi-Fi لا يثبت عبور بث SwimTime؛ بعض نقاط الوصول تمنع Broadcast.

في Hy-Tek اترك Standard، وفعّل Create result automatically أثناء التجربة المتفق عليها. اترك Auto import start list غير مفعّل حتى تجهيز القائمة الصحيحة. احتفظ بنسخة من مجلد التبادل:

C:\Users\Public\Documents\SwimTime\Exchange

لفحص GEN افتح Connections وارفع نسخة الملف. لاستكمال تبني النتائج نحتاج ملف النتيجة وتقرير الشوط نفسه وقائمة البداية. لا تفاضل الحزمة تلقائيًا بين P0001 وP0002، ولا تختار عمود الزمن الأساسي أو الاحتياطي دون تحقق.

أداة deployment\LIST_SWIMTIME_PORTS.ps1 تعرض اتصالات عملية SwimTime للقراءة فقط. منفذ UDP المحلي المعروض ليس بالضرورة منفذ الوجهة. بعد تأكيد منفذ الوجهة من فحص حركة فعلي يمكن تسجيل نسخة خام، خارج السباق، بهذا الأمر:

.venv\Scripts\python.exe -m alge_gateway.record_udp --port CONFIRMED_PORT --seconds 60

استبدل CONFIRMED_PORT برقم مثبت، ولا تخمّنه. الأداة تسجل البايتات كما وصلت ولا تفسرها أو تغير جهاز التوقيت. الملف داخل runtime/captures؛ أرسل عينة التسجيل لاستكمال البروفايل.

اعتماد النتائج بحساب واحد

الحساب الواحد يجمع عمليات البرنامج؛ مسؤولية الاعتماد تبقى لدى المسؤولين المخولين. يحتفظ المسار بتجميع النتائج غير الرسمية ثم المراجعة ثم تسجيل اعتماد المسؤول ونشر النتيجة. عند Record external Chief endorsement أو Record external Jury approval يجب إدخال اسم صاحب الاعتماد الخارجي ومرجع المستند. يسجل النظام أن operator أدخل القرار نيابة عن الجهة المذكورة؛ لا يتحقق برمجيًا من صحة توقيع المستند ولا يدّعي حسابين مستقلين.

لا تُسجل موافقة لم تصدر فعليًا. بيانات TEST ومراجع TEST للاختبار فقط. تعديل النتيجة المعتمد يحتفظ بسجل التوقيت الخام ويُلغي الاعتمادات السابقة؛ الجرافيك لا يغيّر مصدر زمن السباق.

شاشات LED والهوية

تصحيح مصدر الهوية إلى أصول FISU/SFS داخل مجلد Live Results مضمّن. الهوية البنفسجية والماسكوت السابقان غير مستخدمين للنتائج. أصل BAR_BASIC_WITH_BLUE.TGA ناقص، واسم SFS_CLOCK.TGA مقابل CSP_clock.tga غير محسوم، وأصول ميداليات ناقصة. لذلك لا توجد مطابقة بصرية كاملة أو موافقة إنتاجية. لا تستبدل الحزمة هذه العناصر بصمت.

الحفظ والاستعادة

استخدم Audit & recovery ثم Create consistent backup. احتفظ بنسخة من ملف النسخ الاحتياطي في وسيط مستقل. قبل تبديل إصدار أو قاعدة بيانات أوقف الخادم بـ Ctrl+C؛ لا تستبدل قاعدة مفتوحة. للاستعادة اتبع Windows_Installation_and_Recovery.md وأداة CLI المضمّنة، مع تحديد مسار قاعدة single_test أو single_venue الصحيح. الرجوع إلى v0.6 يتم بتشغيل مجلده الأصلي الذي احتفظت به، وليس نسخ ملفاته فوق v0.7.

أدلة الاختبار وحدود التسليم

راجع Release_v07_Status.json وتقارير testing/reports/v07_*. التقارير الأقدم هي أدلة تاريخية للإصدار السابق ولا تمثل اختبارات جديدة. جميع الاختبارات الآلية الجديدة تعمل على Linux/Chromium ومحاكاة محلية؛ لا تثبت تشغيل Windows أو OBS أو Wi-Fi أو ALGE في الموقع. اعتماد الإنتاج ما زال معلقًا.
